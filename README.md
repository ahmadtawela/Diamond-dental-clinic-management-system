# Diamond Clinic Management System

نظام ويب لإدارة أعمال عيادة أسنان من مكان واحد. يجمع ملفات المرضى والمواعيد والسجلات العلاجية والفوترة والتأمين والتقارير في واجهة واحدة، مع صلاحيات مختلفة للمسؤول والطبيب وموظف الاستقبال.


**English**

> Dental clinic management system for patient records, appointments, treatment plans, billing, insurance, and role-based access. Built with Laravel and React.

**العربية**

> نظام لإدارة عيادات الأسنان يشمل ملفات المرضى والمواعيد والخطط العلاجية والفوترة والتأمين، مع صلاحيات حسب الدور. مبني باستخدام Laravel وReact.

## المزايا

- إدارة ملفات المرضى والبحث فيها وتعديلها وأرشفتها.
- تنظيم المواعيد حسب الطبيب والتاريخ، مع عرض يومي وشهري وتحديث حالة الموعد.
- حفظ التاريخ الطبي ومخطط الأسنان وخطط العلاج والزيارات والوصفات الطبية.
- رفع صور الأشعة والمرفقات وعرض الصور داخل التطبيق.
- إدارة الفواتير والمدفوعات وشركات التأمين والمطالبات التأمينية.
- تقارير الإيرادات وإحصاءات المرضى وإدارة المستخدمين والأدوار.
- واجهة تدعم العربية والإنجليزية واتجاهي العرض RTL وLTR، وتتكيف مع الشاشات الصغيرة.
- صلاحيات مرتبطة بالأدوار، يفرضها الخادم على نقاط API، إضافة إلى التحكم بما يظهر في الواجهة.

## الأدوار والصلاحيات

| الدور | نطاق الوصول |
|---|---|
| المسؤول (`admin`) | إدارة المرضى والبيانات السريرية والمواعيد والفوترة والتأمين والتقارير والمستخدمين. |
| الطبيب (`doctor`) | إدارة المرضى والمواعيد والسجلات السريرية وخطط العلاج والزيارات والوصفات والمرفقات. لا تظهر له أقسام الفوترة أو الإدارة. |
| موظف الاستقبال (`receptionist`) | إدارة بيانات المرضى الأساسية والمواعيد والفوترة والتأمين، مع عرض فقط لمخطط الأسنان وخطط العلاج. لا يمكنه الوصول إلى السجلات السريرية الخاصة أو التقارير أو إدارة المستخدمين. |

يمكن إنشاء حساب موظف استقبال من التسجيل، لكن الحساب يبقى غير نشط حتى يفعّله المسؤول.

## التقنيات

- **الواجهة الأمامية:** React 18، Vite، React Router، Tailwind CSS، Axios، Recharts.
- **الخلفية:** Laravel 12، PHP 8.2 أو أحدث، Laravel Sanctum للمصادقة وإصدار رموز API.
- **قاعدة البيانات:**mysql افتراضياً، مع إعدادات Laravel المتاحة لقواعد بيانات أخرى مثل MySQL.

## متطلبات التشغيل

- PHP 8.2 أو أحدث مع إضافات PHP التي يتطلبها Laravel.
- Composer.
- Node.js وnpm.
- MySql للتشغيل بالإعداد الافتراضي، أو خادم قاعدة بيانات آخر عند ضبط ملف البيئة.

## التشغيل محلياً على Windows

افتح نافذتي PowerShell من مجلد المشروع، واحدة للخلفية وأخرى للواجهة.

### 1. إعداد وتشغيل الخلفية

```powershell
cd backend\diamond-backend
composer install
Copy-Item .env.example .env
php artisan key:generate
php artisan migrate --seed
php artisan storage:link
php artisan serve
```

تعمل واجهة API افتراضياً على `http://localhost:8000/api/v1`.

يستخدم الإعداد الافتراضي MySql. إذا لم يكن ملف قاعدة البيانات موجوداً، أنشئ الملف `database\database.MySql` قبل تنفيذ الترحيلات. لا تستخدم `migrate:fresh` على قاعدة بيانات تحتوي بيانات تريد الاحتفاظ بها.

### 2. إعداد وتشغيل الواجهة

في نافذة PowerShell ثانية:

```powershell
cd frontend
npm install
Copy-Item .env.example .env
npm run dev
```

افتح عنوان Vite الظاهر في الطرفية (عادةً `http://localhost:3000`). عنوان API الافتراضي للواجهة هو `http://localhost:8000/api/v1`، ويمكن تغييره في `frontend\.env` عبر `VITE_API_URL`.

### حسابات التطوير الأولية

ينشئ الأمر `php artisan migrate --seed` حسابي التطوير التاليين:

| الدور | البريد الإلكتروني | كلمة المرور |
|---|---|---|
| المسؤول | `admin@diamond-clinic.test` | `12345678` |
| الطبيب | `doctor@diamond-clinic.test` | `123456789` |

هذه بيانات محلية تجريبية فقط. غيّرها أو عطّل الحسابات الافتراضية قبل نشر التطبيق، ولا تستخدمها في بيئة إنتاج.

## بنية المشروع

```text
backend/
  diamond-backend/   Laravel API، المصادقة، نماذج البيانات، الترحيلات والاختبارات
frontend/
  src/               تطبيق React، الصفحات والمكونات والسياق وعميل API
```

تتضمن نقاط API بادئة الإصدار `/api/v1`. تتطلب المسارات المحمية تسجيل الدخول، وتطبّق الخلفية صلاحيات الدور قبل إتاحة البيانات أو تنفيذ العمليات.
